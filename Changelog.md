# Changelog

## 2.0.0

The first release of Video Destroyer as an app. It builds training datasets from video as a node graph, run by a VapourSynth dataset engine, and replaces video-destroyer and VSR-Dataset-Creator. It is built on Vapourkit's installer and inference backends.

- **A dataset job is a node graph.** Connect sources, degradations, sequence pickers and filters to a writer, check the job, run it, and save it as a `.vkdataset` file. The palette, the ports and each node's settings come from the engine, and New starts from an example or an empty job
- **Example workflows** to start from, from a six-node first dataset to aligned pairs from two releases, each laid out left to right with a note on every node. Every node has a plain name, a description of what it does and when to use it, named ports, and a stage (Load, Prepare, Split, Degrade, Clean up, Pick, Filter, Save) that gives the intended order
- **A quiet node editor.** The workspace opens on the numbered example workflows, one line each. Node cards are compact, in the style of Blender's and Unreal's node editors: a header tinted in the stage's colour (so a chain reads Load to Save by colour), a one-line note, outputs then inputs with plain port names, how often a node runs, a greyed Off state, and one row per setting with the label left and the value right (the first seven, in the order the node declares them, the rest behind "N more"). A random setting shows its range as "low – high" and picks fixed, range, int range or list from a dice menu at the row end; code and JSON open from a one-line preview. What a node does is behind its "?", and rename, note and delete are in its "…" menu. Wires take their port type's colour, the selected node's wires stay bright while the others dim, and a wire that runs back left or drops to a lower row turns at right angles. Holding Alt colours the chain by step, green at the start to red at the end, with a step number on each card. There is no side panel, so the canvas takes the whole width. The palette lists node names under folding stage headers and is searchable, and a click adds a node after the selected one, joined to it when there is only one way. The canvas shades the nodes that run once per chunk, and Arrange lays a job out left to right with the HR path above the LR path. Problems open from their count in the bottom bar, and an edge that runs back through the stages is dashed, with the hint on hover
- **One video into HR/LR pairs** (video-destroyer): split by scene, duration or frame count, then degrade the LR side per chunk, or with any ffmpeg filter. HDR sources can be tonemapped to SDR first
- **Realistic degradations**, modelled on how real releases are made, with settings fixed per chunk and grain new on every frame: Lens Blur (Real-ESRGAN kernel shapes), Film Grain, Sensor Noise, Resample (anamorphic DVD frames, varied kernels, gamma or linear light), Sharpen (DVD halos), Chroma Bleed, Telecine (3:2 pulldown, or native interlaced video) and Bad Telecine Fix (failed field matching, then combing, blending, bob or bwdif, back to one LR frame per HR frame; the job check asks for a fix after every Telecine), Banding, Compression with named profiles (DVD and broadcast MPEG-2 with real buffer, GOP and B-frame settings, web H.264/H.265, Xvid; bitrate per pixel; a rip of a rip is a second Compression), Player Deblock, Player DNR, Chroma Subsampling (bad player upsampling, wrong siting, the interlaced chroma error), Ghost Echo and Scale to Model Size. The "DVD anime" example follows a DVD anime chain
- **Analogue video chain**: the LR side recorded to a simulated VHS tape and played back over NTSC composite by ntsc-simulator's VapourSynth plugin, as four device nodes: Composite Encode, VHS Tape (lq/mq/hq tapes, dubs), Playback Deck (consumer, S-VHS TBC, edit, vhs-decode) and Composite Decode. One tape can feed several decks. The "VHS tape" example uses them
- **Two releases into aligned pairs** (VSR-Dataset-Creator): the LR release is matched to the HR one in time, then each HR target is warped onto its LR frames with vs_align. Pick Aligned Sequences takes each scene's best run, Cut into Tiles crops it where detail and motion are, Drop Misaligned drops runs out of sync and crops that do not line up, and near-duplicates can be removed. The default layout is 9 LR frames per sequence with the centre frame as the HR target
- **HR processing** of an existing dataset into `hr_p/`: Fast Line Darken, Fine Dehalo, Match Gamma, brightness/contrast/gamma, and ONNX models for denoise, de-H264 and colour correction. A denoise dataset can be built from static shots, and `rename` renumbers a dataset after culling
- **Graph combinators.** Random Branch picks one of up to four inputs per chunk by weight and runs only that branch; the pick is in the manifest and the preview, and each input's share shows on its port. Blend mixes two inputs by a per-chunk weight. Brightness, Edge, Flat Area and Motion masks (with Combine Masks) feed Masked Merge, and a mask has its own port colour and previews as a picture. Writers take a subfolder, so several share one dataset folder, and variants, which write each sequence again with fresh LR draws. Examples 10 to 14: mixed sources, damage where it happens, one source to three datasets, clean HR with damaged LR, and real pairs with extra damage
- **Random settings are reproducible.** Any setting can be a fixed value, a range or a list to pick from, and a dropdown can pick at random among the options you tick, with optional weights. Each chunk draws its own values from the job's seed, and `manifest.json` records them for every sequence, so the same seed gives the same dataset. H.264 encodes run on one thread, as x264's rate cap encodes differently on every run otherwise
- **Settings driven by wires.** Any setting row can take a value wire, Blender style: a small socket on the row's left edge shows on hover and while a value wire is drawn, and a linked row shows the value node it comes from (with its value for the previewed chunk) instead of its editor. Four value nodes, under Values in the palette, give one value per chunk from the job's seed: Random Number, Random Pick (ticked from the options of the dropdown it feeds, with weights), Math and If Equals. One pick can drive two nodes, one setting can be worked out from another, and one can depend on another, such as a size that follows the profile. A value that a setting can never take (an option its dropdown lacks, a range past its limits) is refused when the job loads, and anything else when it arrives. Linked values are in the manifest like any draw, a value node shows its value on its card while the preview runs, and value wires stay out of the chain steps and Arrange puts value nodes above the nodes they feed. Example 17 shares one profile between an upload and its re-encode, and works out the re-encode's quality from the upload's
- **Preview any node** before running: the Preview panel shows a node's output for one chunk of one video exactly as a run would make it, with what every node drew for that chunk, and for sequences the kept and rejected crops with the reason. Compare two outputs side by side or with a wipe (an LR picture is scaled up with nearest pixels by default), scrub the chunk's frames, zoom to 100% or 200%, and reroll the draws without changing the job's seed, or adopt the rerolled seed. A chunk is computed once, so scrubbing is instant after the first frame; nothing is written
- **Filters** drop blank, static, over-moving or incomplete sequences, and can write them to a separate folder for review. Tiling cuts sequences into matching HR and LR tiles, on a grid or where detail is
- **Model nodes** run ONNX files through vs-mlrt on TensorRT, DirectML, NCNN Vulkan or MIGraphX. No model weights are bundled
- **Model nodes follow a Default AI backend.** Settings lists the backends this machine can use, and Auto picks the best of them; a node set to "auto" runs on it, and a backend chosen on the node wins. Runs and previews pass the choice to the engine together with the TensorRT engine builder's paths, and the run log says which backend each model node uses and shows TensorRT engine builds as they go
- **First-run setup** installs a private Python with VapourSynth, FFmpeg on Windows, and Vapourkit's filter set minus the vsview viewer: vsjetpack with the GPU's extras (pinned to 2.2.0, the last release that accepts the vs-mlrt pins), pifroggi's vs_temporalfix, vs_undistort, vs_grain, vs_tiletools, vs_colorfix and vs_deepdeinterlace (from GitHub at a pinned commit), MVTools, CAS, AdaptiveGrain, WNNM, NLM CUDA, SCXviD, DCTFilter and timecube, plus vs-mlrt for the GPU, vs_align, PyTorch, OpenCV and ONNX Runtime. The Hybrid scripts are downloaded into `vs-scripts` at a pinned commit, and `plugins.7z` now carries only the four plugins with no wheel (TCanny, MiscFilters, EEDI2CUDA, cv_inpaint). An NVIDIA install downloads about 6.3 GB and takes 9.7 GB with FFmpeg. PLUGINS.md lists every package with its licence. Plugins reinstalls or removes them; Settings holds the Default AI backend, the ROCm choice for MIGraphX on Linux, the appearance and the folders
- **Filter Template node** runs any of 138 of Vapourkit's VapourSynth filter templates (denoise, deinterlace, IVTC, colour fix, dehalo, deband, masks and more) on a clip, with the template's code shown and editable. The code sees `clip`, `core`, `vs`, `original_clip` (an optional Reference input) and `VK_BACKEND` as in Vapourkit, plus a seeded `rng` whose draws go into the manifest
- **Update check**: the app says when a newer release is out on GitHub
